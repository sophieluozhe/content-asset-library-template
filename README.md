# 内容资产库模板（开源版）

一个基于 Markdown 和 Obsidian 原生链接的内容资产库模板。它帮助你把原始输入加工为可追溯的原子资产，再组合为主题、短视频、公众号与朋友圈内容，并记录发布复盘。

它不是把一篇文章拆成许多零散摘抄，而是把内容沉淀为可验证、可组合、可复用的八类资产：判断有观点卡支撑，做法有方法卡展开，案例同时配上证据、反例和适用边界。这样同一组资产可以服务不同主题和不同平台，而不会因发布一次就失效。

## 工作流

原始材料 → 清洗稿 → 原子资产 → 主题 → 内容单 → 发布 → 复盘 → 新资产

原始材料永远保留；清洗稿和资产卡必须回链来源，并标注页码、时间戳或段落锚点。

## 核心：八类原子资产

原子资产是这套库的最小复用单位。它们不是按内容形式分类，而是按内容在论证和创作中承担的角色分类。

| 资产类型 | 它回答的问题 | 用途 |
| --- | --- | --- |
| 观点卡 | “我主张什么？” | 沉淀一个可被讨论、支持或挑战的判断。 |
| 方法卡 | “具体怎么做？” | 记录可执行的步骤、原则或框架。 |
| 案例卡 | “有人是怎样做到的？” | 记录真实做法、过程与结果。 |
| 反例卡 | “它会在什么情况下失效？” | 记录失败情境，用来挑战某个观点或方法。 |
| 边界卡 | “它在哪些前提下才成立？” | 明确适用前提与不适用情境，限制过度泛化。 |
| 定义卡 | “这个概念究竟是什么？” | 固定关键概念的含义，并与相近概念区分。 |
| 证据卡 | “凭什么这样说？” | 保存数据、原话或研究，并关联它支持的观点。 |
| 故事卡 | “如何让人愿意听下去？” | 提取场景、冲突和转折，供内容表达使用。 |

它们之间有明确关系：**证据支持观点，反例挑战观点或方法，边界限制观点或方法，案例展示做法与结果**。金句不单独建卡，而是放在相应观点卡、故事卡或方法卡的“可直接引用表达”里，避免脱离语境。

每张原子资产卡都带有来源、原文锚点、置信度、使用状态和适用平台字段。因此，一条内容从哪里来、是否可公开、还能不能再次使用，都能被追溯。

## 开始使用

1. 在 Obsidian 中将本目录作为独立库打开。
2. 从 [模板索引](99%20模板/模板索引.md) 选择“原始材料登记模板”，登记自己的输入。
3. 在 [资产加工看板](00%20内容控制台/资产加工看板.md) 手动维护清洗和萃取状态。
4. 用八类原子资产模板沉淀可复用内容；再用主题和内容单模板进行生产。
5. 发布后填写复盘，并将新的线索回流为资产或输入。

## 在 Obsidian 中使用

本模板主要面向 Obsidian 用户。下载并解压后，在 Obsidian 中选择“打开已有库”，直接选中本文件夹即可。

模板内部采用标准 Markdown 链接，例如 `[模板索引](99%20模板/模板索引.md)`，而不是只使用 Obsidian 专属的 `[[双链]]`。这是有意的：Markdown 链接在 Obsidian 中可以正常点击和跳转，同时也能在 GitHub 和其他 Markdown 工具中使用，因此不需要先把模板转换成双链。

如果你只在 Obsidian 内使用，可以在“设置 → 文件与链接”中开启“自动更新内部链接”。开启后，无论模板使用的是双链还是 Markdown 内部链接，在 Obsidian 文件列表中改名时，Obsidian 都会尝试同步更新链接。不要直接在 Windows 文件资源管理器里改名后期待 Obsidian 自动修复。两种链接都能在 Obsidian 中工作，区别主要是跨平台兼容性和链接语法习惯。

## 目录与层级

```text
00 内容控制台/
├── 资产加工看板：追踪“待清洗 → 待萃取 → 已完成”等加工状态
├── 内容生产看板：追踪“待策划 → 待发布 → 已发布”等生产状态
├── 发布日历：按发布日期查看内容单
└── 发布复盘：汇总发布后的反馈与可回流资产

01 输入资产/
├── 01 原始材料：录音转写、笔记、观察等原件，只保留、不覆盖
├── 02 清洗工作台：正在整理的材料
├── 03 清洗完成：保留来源锚点的清洗稿
├── 04 萃取工作台：从清洗稿提取资产的过程记录
└── 05 已萃取来源：已完成萃取的来源索引

02 原子资产/
├── 观点卡/、方法卡/、案例卡/、反例卡/
└── 边界卡/、定义卡/、证据卡/、故事卡/

03 主题库/：围绕一个核心问题与核心主张，组织关联的原子资产。

04 内容单/
├── 短视频/：脚本与镜头表达
├── 公众号/：长文内容单
└── 朋友圈/：短表达内容单

05 已发布归档/：保留已发布内容、链接与复盘入口。

99 模板/：输入加工、八类原子资产、主题、三类内容单和发布复盘模板。
```

## 隐私边界

本仓库只包含模板、通用说明、空控制台和虚构演示。请勿提交真实录音、转写、客户或个人信息、真实发布链接、业务数据或 Obsidian 配置。提交前请阅读 [隐私检查说明](PRIVACY_CHECK.md) 并运行检查脚本。

在 Git 仓库中暂存准备公开的文件后，运行：

```powershell
pwsh -NoProfile -File scripts/check_release.ps1 -RepositoryPath .
```

检查器会拒绝空白名单、未在 `release_allowlist.txt` 中列出的暂存文件、`.obsidian`、软链接、子模块、含 NUL 字节的文件，以及缺少“虚构演示”标记的演示 Markdown。
